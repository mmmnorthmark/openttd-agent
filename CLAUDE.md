# openttd-agent

Shared package (public): CLI + MCP + AgentBridge GameScript for agent-driven OpenTTD companies on a LAN.
Research and design history: ~/code-local/openttd-agent-research/FINDINGS.md.

- Access model (0.2.0): players never get the admin password. Host runs `openttd-agent relay` (`src/relay.js`, port 47978): the only admin-port client; per-player tokens (`src/relay-players.js`, SHA-256 only, `~/.openttd-agent/relay-players.json`), company forced per request, audit in `relay-audit.jsonl`. Commands run on the relay (shared map mirror); a player's `runCommand` forwards any `session: true` command when `cfg.relay` is set (`src/relay-client.js`).
- Relay policy is `authorize()` in `src/relay.js`: groups game/world/build/operate only; a new group is host-only until added there. Every command that changes the game or reads company data must take `company` (use `who`/`act`) or the relay cannot force it; `test/relay.test.js` fails otherwise.
- OpenTTD 15.3 cannot bind the admin port separately from the game port (one bind list, `GetBindAddresses` in network.cpp).
- One command registry: `src/commands.js`. CLI (`bin/`), daemon (`src/daemon.js`) and MCP (`src/mcp.js`) are thin wrappers. Add commands only there.
- GS ↔ admin protocol: `docs/PROTOCOL.md`. Keep GS replies < 1100 B; return arrays for big data.
- Bump `GetVersion()` in `gamescript/AgentBridge/info.nut` whenever main.nut changes, and `bridge_version` in main.nut's `info` reply with it (clients gate features on it; a unit test checks they match).
- Releases (Matthew, 2026-11-25): semver, one annotated tag `vX.Y.Z` per release. Release commit = package.json version + dated CHANGELOG section + README `#vX.Y.Z` references. `main` may run ahead under "(unreleased)". Agents commit and tag locally (NAS backup is automatic); Matthew pushes to GitHub with `--follow-tags`.
- Public = generic mechanism only (explicit params, neutral defaults). Strategy, recipes, drivers and prompts belong to the private skills repo; never reference it here. No personal names, paths or IPs in code, tests or docs.
- Tests: `npm test` (fake admin server in test/fake-server.js mirrors GS commands; extend it with every new GS command).
- Verified GS API names against OpenTTD 15.3 headers (src/script/api). Check new ones the same way before use.
- State changes are **exec steps**: add an op to `ExecStep` in main.nut, mirror it in the fake server's `exec`, and build the step list in the command (`run(ctx, a, steps)`). Never add a one-off GS build handler.
- Row decoders for operate data live in `src/operate.js` (pure, unit-tested).
- Not exposed to GameScripts in 15.3 (don't promise them): vehicle breakdown count, service interval, vehicle-lost/unprofitable/engine-available events, production-change events.
- No Squirrel compiler on this machine: errors show only in the launch profile's `openttd.log` (`-d script=4`). Before a real run, check API calls with `python3 -I tools/check_gs_api.py <headers dir> gamescript/AgentBridge/main.nut`.
- GS rules learned in the first real run (0.1.0): never dispatch through `.call()`/`acall()` or sort/valuator callbacks around DoCommands (a native call on the stack makes any DoCommand fatal and the script dies silently); company-scoped getters without a company arg (`GetLoanAmount`) need `GSCompanyMode`; a script death logs only "The script died unexpectedly".
- OpenTTD with `-c`: the cfg's folder becomes config + personal dir (secrets.cfg, saves, log); `~/Documents/OpenTTD` is still scanned for baseset/game/ai. secrets.cfg is ignored unless openttd.cfg has `[version] ini_version` >= 1 (launch writes 7).
- Real-game test loop: `launch --mode dedicated --admin_password <pw> --bind 127.0.0.1 [--terrain mountainous --map_bits 9]`, then rcon `start_ai IdleAI` for a company (id 0). Relay check: `relay-add-player --name t --company 0`, `relay`, then a second `OPENTTD_AGENT_HOME` with `configure --relay http://127.0.0.1:47978 --token <t>`; `relay-remove-player` after. Tested 0.1.0: map mirror 2.2 s (256²) / 8.4 s (512²); ~35 dry-run builds/s via `batch`.
- Path planning and build templates are pure functions in `src/planner.js` (`planPath`, `railSteps`, `roadSteps`, `terminusSteps`, `passingLoopSteps`); test them on synthetic maps in `test/planner.test.js`.
- Rail `build-rail` anchors get no track (verified in play). Joining onto existing track (depots, branches) needs `build-track`. Signal facing verified in play (2026-11-26): `GSRail.BuildSignal/GetSignalType(tile, front)` is the signal facing trains that come FROM `front`; `rail_tiles` bit 4+d / one-way bit d = signal facing trains from neighbour d. A one-way signal blocks trains entering through the opposite edge (`entryRefusal`; it was inverted before 0.7.0). Trains stop on the tile before a red signal, not on the signal tile.
- Command groups: `host` = needs the game but host-only (goals, pause, turns); the relay serves only game/world/build/operate. Host commands that load games (`scenario-prepare`) are `session: false` with their own `AdminClient`, because a load makes every session stale (context.js drops the session on `newgame`; a load is finished at the second `welcome`).
- A loaded scenario/save runs only the GameScript in its `GSDT` chunk (15.3 game_sl.cpp). `scenario-prepare` (`src/scenario.js`) splices ours in with `src/savegame.js`, which reads only uncompressed saves: launch profiles set `[misc] savegame_format = none` (read at startup; OpenTTD rewrites the cfg on exit, so patch with `patchIni`, never append a second `[misc]`).
- Game settings of a loaded save come from the save (PATS chunk), not the cfg. The console refuses `command_pause_level` (NoNetwork flag) and `script_max_opcode_till_suspend` (NewgameOnly) in a network game, so `scenario-prepare` sets both in PATS (`patchTableFields`).
- Console facts (15.3, verified): `save` returns before the file is complete (threaded) so poll until it parses; `pwd` prints the save folder; `load <name>` needs an `ls` first to see a new file; `content update` is asynchronous (poll `content state` until the row count is stable); a downloaded scenario shows in `list_scenarios` as "<content name> (<version>)" without a restart; a game saved paused loads paused; console `companies` numbers from 1, the GS from 0.
- Goals live in the GS (`CmdGoalSet` etc. in main.nut). Deliveries: sum `GSCargoMonitor.GetTownDeliveryAmount` over all towns only; industry deliveries are already in the town monitors (adding industry monitors double counts). GSGoal calls need deity mode (no `GSCompanyMode` on the stack) and take raw strings. `Save()` only returns fields already in memory; `Load()` only stores the table, `Start()` validates it (`RestoreGoals`). info.nut has `MinVersionToLoad` 5: without it a save made by an older version starts the script without its data.
- Turn-based play: GS keeps answering and DoCommands execute while paused; building while paused needs `command_pause_level = 3` (verified: stations, depot, vehicles, orders, goals all work paused). A game day is ~2.0 s on a dedicated server (measured: 30 days in 60 s); `turn-advance` polls `info.date`.
- Real-game test loop for scenarios: `scenario-prepare --content_id 15847807 --load true` (Mini Empire Builder 64x64, two towns; a bus stop at the town edge does not accept passengers, so test deliveries with a central stop), console `start_ai IdleAI`, `pause`, `goal-set`, `turn-advance`.
- Composite commands (`build-cargo-route`) reuse the command bodies through shared functions in commands.js (`stationSites`, `lineDepot`); pure parts in `src/route.js`. Plan on not-yet-built things with `overlayMap` (planned stations 's', planned track 'r'). Each CLI call costs a weak model minutes, so composites matter.
- AgentBridge v7 adds `acceptance` (GSTile.GetCargoAcceptance, no company mode needed). Commands degrade when the running GS is older ("unknown cmd": `acceptanceAt` returns null) because a new GS is live only after the game is loaded again.
- AgentBridge v8 adds the `loan` exec step (`LoanStep` in main.nut): own refusal texts, because `GSCompany.SetLoanAmount` preconditions fail with a bare ERR_PRECONDITION_FAILED. The `loan` command reads before/after from GS `companies`; a dry run predicts the after values. Not yet checked in a live game.
- The CLI talks to a background daemon that keeps the code it started with: after changing src/, run `daemon-stop` before testing live (the next call starts a fresh one).
- GS rail type order: `GSRailTypeList` lists electrified (1) before normal (0) in 15.3, so the build-rail default is electrified; build-cargo-route defaults to the cheapest track.
- 15.3 temperate: the 'Dash' and the DMU are railcars with their own passenger capacity; `pickTrain` skips other-cargo railcars when a real locomotive exists.
- AgentBridge v9 adds `rail_tiles` (track bits, depot front, bridge/tunnel other end, signals per tile; max 32x32). Connectivity is traced in the client (`src/connectivity.js`, pure, tested), not in the GS. `vehicle-problems`/`verify-route` fall back to a coarse mirror flood when the running GS is older (the mirror has classes only; depots, bridge heads and tunnel portals are 'o'). The mirror's coarse trace merges lines that touch, so trust it only for "not connected".
- `vehicle-problems` keeps the stuck/lost history in the Session (`s.vehicleHistory`, keyed company:vehicle): it works with any GS and costs the game nothing, but restarts with the daemon.
- Lost is inferred: ScriptEventVehicleLost is AI-only. Clones keep their orders, so a train cloned (or bought by build-cargo-route before 0c2f525) in another line's depot is `wrong_network`.
- Ideas ported from other projects are credited in NOTICE (no copied code). Keep licences straight: MIT and Apache-2.0 ideas only; GPL projects ideas only too.
- `vehicle-clone` (and `vehicle-buy --route_of`) check the depot with `depotForRoute` in commands.js: trace depot -> every order station; `--depot auto` tries the nearest 8 depots to the first order station. Verified live on GS v9 (2026-11-25): 64x64 map, 20 trains: `vehicles` 2.5 KB in 3 parts, `rail_tiles` 32x32 up to 4.8 KB in 5 parts (largest part 1057 B), ~25 ms per call; verify-route ~0.4 s, vehicle-problems ~0.7 s.
- AgentBridge v10 adds owned land: `buy_land` exec step (`BuyLandStep`: check all tiles, test-mode estimate, then buy row by row; `GSObjectType.BuildObject(3, 0, tile)` under company mode) and the `owned_land` query. The GS API has no object type at a tile: `IsOwnLand` = owned by the company, no rail/road/water transport, not a station, not buildable, and a test-mode `DemolishTile` succeeds with cost <= 0 (owned land has ClearIncome; HQ and statues cannot be removed). Owned land is class 'o' in the mirror; `owned-land` sends only 'o' tiles. Pure helpers in `src/land.js`. Not yet checked in a live game.
- 0.7.0 result envelope (`src/envelope.js`): `runCommand` wraps every result: `ok`, `error` (null on success), `first_error` (code: ERR_* or our snake_case `code: text` prefix). Lists use `listResult(key, all, matched, limit)`; never return a bare array. Own refusal texts start with `code: ` so `errorCode` picks the code. `execSummary` marks dry-run signal steps on track the same list lays as `skipped_in_dry_run` (`markDryRunSkips`).
- AgentBridge v11: `road_tiles` query (rows `[x, y, kind, links, station, a, b, owner]`, links from `GSRoad.AreRoadTilesConnected`, so one-way roads count) and `DepotStep` (`veh_depot`: never re-sends a vehicle already heading to a depot, which would cancel it; value 1 sent / 2 heading / 3 in depot). Road tracing is client-side (`traceRoad` in connectivity.js); older GS: road verify-route is refused, never answered with rail. Verified live 2026-11-26 (256x256 very_flat): bus route trace, gap no_road, road stop/depot `connected`, `--connect auto`, drive-through on a junction decoded from ERR_UNKNOWN.
- `build-passing-loop` (verified live 2026-11-26: two 2-tile trains passed each other in a length-4 loop twice, no deadlock): main side for trains heading `dir`, loop side for the others; one-way signals at P(length,0) and P(2,1) give both sides length-1 clear tiles. Site check, `loop_check`, `route_after` and `--remove` live-tested.
- Player profiles: global `--profile NAME` (bin strips it anywhere on the line) / `OPENTTD_AGENT_PROFILE` / `OPENTTD_AGENT_PLAYER_FILE`; `loadConfig` merges config.json < profile < env; `saveConfig` writes to the profile when one is active. A direct-mode profile runs in-process (the daemon uses the base config).
- Relay rival reads: `RIVAL_READS` in relay.js (`stations`, `vehicles`); the commands trim a rival's view themselves (`isRival`: company != cfg.company).
- `launch` rewrites the profile's `[game_scripts]` to AgentBridge only (`replaceIniSection`) and writes `server_name`/`client_name` to the profile's private.cfg (OpenTTD 15 ignores them in openttd.cfg). `--bind <one address>` saves it as `host`. The daemon reports its version on /health and the CLI restarts a daemon of another version (same-version code edits still need `daemon-stop`).
- A Session whose GS does not answer closes its admin connection (a retrying daemon used to fill the server's admin slots: ECONNRESET).
- AgentBridge v12 (batch 2 of 0.7.0): `veh_reverse`, `sign`/`sign_remove`, `hq` steps; `company_history`, `rating_parts`, `station_vehicles`, `tile_owners`, `vehicle_wagons`, `signs`, `road_types` queries; `companies` rows gain `station_count`/`vehicles_by_type`, `depots` rows the front tile. Commands needing v12 refuse clearly (`needV12`) or degrade (stations without `vehicle_ids`, tiles without owner marks).
- OpenTTD `UnshareOrders` (CO_UNSHARE) leaves the vehicle with NO orders (verified live): to give a vehicle its own copy, unshare then `orders_copy` share=false from a vehicle of the group. A clone with share=true joins the source's group at once, so read `shared_orders` after cloning, not before.
- Long-lived jobs live in the Session (daemon or relay): `pendingSales` (vehicle-replace sells on arrival), `pendingWagons` (train-add-wagons), `watchVehicles` (15 s stall samples per company once vehicle-problems ran), `_autoSave` (save --every_months). `finishSales()` runs both vehicle queues; timers are unref'd and stop when empty. All end when the daemon restarts (`daemon-stop` after code changes drops them).
- A train's `SendVehicleToDepot` fails (no_depot) when no depot is ahead of it; it finds one after turning. train-add-wagons retries every 20 s.
- `traceRail` returns `path` (ordered tiles) when connected; loop-sites / --passing_loops / add-train use it. Loop-site and depot-front logic is pure (`loopSites`, `spreadLoops`, `plannedRail` in planner.js; `depotFrontCheck`, `countLoops` in commands.js); truck-route helpers in `src/truck.js`.
- Exec results drop `value` 0 except for steps that create an id (`ID_STEPS` in operate.js: vehicle 0 is real). Relay liveness: `src/relay-stats.js` (relay writes `relay-stats.json`; host reads it with `relay-stats`).
- Verified live 2026-11-26 (256x256, GS v12): loop-sites -> build-passing-loop, vehicle-replace (old sold on arrival), stalled_on_line + vehicle-reverse, rail-tiles, tiles owner marks, vehicle-buy --orders/--start, stations vehicle_ids, rating (estimate 32 vs game 37), companies --history, periodic saves, signs, build-hq, find-cargo-pairs bounds, build-cargo-route fallbacks/warnings/--passing_loops 2, depot front check, add-train, train-add-wagons, build-truck-route. Deadlock live too: a deliberately short loop (length 3, 4-tile trains) jammed two trains; vehicle-problems said deadlock for both, vehicle-reverse on one freed them. Not live: trams (vanilla has no tram type), relay-stats (tested against the test relay).
